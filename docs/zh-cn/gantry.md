# 龙门架第一版：三台 M2006 的相对位置控制

三台电机均连接 CAN1，ID 为横向 1、左升降 2、右升降 3。ID、方向和参数均可在
`rmcs_ws/src/rmcs_bringup/config/gantry.yaml` 修改，重新启动生效。

本版本没有做模拟测试，也没有连接实物。参数是低速调试起点，不是已经验证的实机参数。
软件控制的是 M2006 减速箱输出轴的多圈角度，不是丝杆毫米数或发射架真实 Pitch/Yaw 角。
左右丝杆传动必须相同，才能把经过反向校正的角度差用作高度差的代理；否则需要加入各侧比例换算。

## 文件和运行流程

- `hardware/gantry.cpp`：复用 librmcs 的 CBoard、DjiMotor、Dr16。
  CAN 回调保存反馈，主更新发布电机角度/速度，伙伴 Command 组件在控制器之后发送指令。
  两个 CAN 命令组分别处理 ID 1–4 和 5–8，每组只发送一帧；未使用槽位为零。
- `controller/gantry/gantry_controller.cpp`：读取摇杆和反馈，生成位置目标、执行同步修正及三路双环。
  不在 C 板内运行控制算法。
- `plugins.xml`：注册两种组件。YAML 列出组件及对应参数；连接通过 RMCS 的同名输入输出完成。

硬件层另外记录三台电机和 DBUS 的最后收帧时间。不使用通用 RemoteControl 的遥控来源超时互锁，
避免只有 DR16 时缺乏独立的失联判断。电机反馈超时或 DBUS 超时会让发送侧请求零转矩。
上位机/USB 完全阻塞时，必须依靠板端命令超时停止旧指令，现场需要确认该行为。
SDK 中 CBoard 和 RmcsBoardLite 是不同设备类型；此任务使用 CBoard（USB VID/PID 为
0xA11C/0xD401），不能因为步兵 Hardware 使用 RmcsBoardLite 就沿用其设备描述。
需要适配当前 SDK 的 C 板固件，普通出厂固件不能直接通信。

## 摇杆、使能和相对零位

左摇杆 x 为升降、y 为横向，对应 DR16 的通道 3 和负通道 2。
`pitch_input_sign` 和 `yaw_input_sign` 可设置为 +1 或 -1。需要检查摇杆符号时，可临时在 YAML
的 signals 中加入 `/gantry/stick_pitch` 和 `/gantry/stick_yaw`，
核对上推及右推的符号，再调整符号；不要假定现有默认符号已符合现场需求。

右拨杆 DOWN：请求零转矩；摇杆居中、通信正常、反馈在范围内时允许后续使能。
MIDDLE：请求零转矩，撤销使能准备。
UP：在已完成 DOWN/居中准备后运行；进入 UP 时也需居中，目标从当前反馈开始，不自动回零。
UP 下回中继续位置保持；斜推同时改变两个位置目标。

只有 `enabled: true` 时才采集相对零位和准备使能。首次 DOWN/居中会分别记录三台电机当前位置。
必须先人工确认左右调平、滑块位于安全区域；软件把两侧各自当前位置视作零，不能识别初始歪斜。
这不是寻找机械原点，也不是永久绝对零位。故障恢复不重置该零位；重启后须重新确认并采集。

默认 `enabled: false`。此时可记录电机角度/速度和摇杆输入，但不会主动保持位置。
停机/故障都请求零转矩，不代表制动：未确认丝杆自锁时，必须有机械支撑以防下滑。

## 控制计算

1. 摇杆过死区后转换成目标角速度，乘以实际控制周期，积分成位置目标。
2. 升降两侧使用同一目标；横向使用独立目标。目标在相对行程内限幅。
3. 每台的位置外环为 P，输出目标速度。
4. 同步误差为 `(左角度-左初始角度) - (右角度-右初始角度)`。
   左侧超前时，从左目标速度减去同步修正，在右目标速度上加上修正。
5. 各自速度内环复用 PidCalculator，输出被限制的转矩。

内环默认只有 P，Ki/Kd 为零。PidCalculator 的积分、微分按采样更新，不是连续时间参数；
更改控制频率或启用 Ki/Kd 时需要重新考虑参数尺度。不要直接复制旧 GM6020 调试参数。

单独控制横向时共同升降目标不变，位置环继续工作；这只能保证软件目标和执行器位置保持。
若横向运动改变实际 Pitch，本版本不会做未经测量的补偿。需现场测角度，必要时补充传感器或运动学映射。

## 保护与日志

每侧升降实际相对角度及横向实际角度超出行程，或左右同步差超阈值，立即请求零转矩并锁存故障。
目标限幅不会消除电机惯性产生的越界。保护阈值、输出上限和速度必须按实物可用空间检查。
两侧方向配置必须确保正角度均为物理上升，不能仅要求两台转子转向相同。

`/gantry/state`：0 停机、1 闭环运行（包括回中保持）、2 故障。
`/gantry/fault`：0 无故障、1 电机反馈超时、2 遥控器超时、3 控制周期异常、
4 非有限/异常输入、5 同步差超限、6 实际位置越界。
通信恢复不会自行运行，需 DOWN/居中重新准备，再居中切 UP。
位置或同步故障还需先排除机械问题，使反馈重新满足限值；不要通过重启掩盖歪斜。

CSV 输出 `/tmp/gantry_<timestamp>.csv`，默认 500 Hz 更新、每 5 次记录一次。
精简 CSV 每行共 11 列：index、三个电机角度、同步误差、三个电机反馈年龄、遥控器反馈年龄、state、fault。
index 是序号，feedback_age/remote_age 为距最后收帧的秒数。尚未采零时同步误差为初始值，不能表示机构已调平。
目标、相对角度、速度、转矩、摇杆和控制周期仍保留为内部接口，需要调参时可加回 signals。
这些接口是 RMCS 内部数据，不会自动变成 ROS 话题。

## 编译与现场调试顺序

在仓库根目录运行现有 `build-rmcs`，然后重新加载工作空间环境。
运行：`ros2 launch rmcs_bringup rmcs.launch.py robot:=gantry`。
没有板卡时，真实 Hardware 无法完成连接；本版本没有无硬件启动模式。

1. 核对 rmcs-board 固件与当前 librmcs SDK 匹配，确认 CAN1 和 DBUS 接线，以及三个 C610 的唯一 ID。
2. 保持 enabled=false，手动转动/安全移动各轴，检查各自角度变化、反馈间隔和摇杆符号。
   只在带电、持续收帧时检查多圈角度；重启、断电或丢帧期间的转数不可恢复。
3. 根据实际移动方向修改各电机 reversed。确认左右反馈正方向均对应上升。
4. 人工调平并摆在安全区；核对相对角度范围对应的实际可移动距离，准备机械支撑和停机方式。
5. 再设 enabled=true，DOWN/居中采零，居中切 UP。先观察回中保持，随后小幅升降。
6. 观察同步误差和输出；若一侧不动、转矩饱和或方向错误，立即停机排查，不能只增大保护阈值。
7. 测试横向、小幅斜推与回中保持。记录实际 Pitch 是否随横向移动变化。
8. 在机构有支撑、运动风险可控时，验证遥控器失联、反馈丢失及板端命令超时；最后才扩大行程和速度。

未经实物调试，不能宣称满足“无明显歪斜”和“Yaw 单独运动时实际 Pitch 不变”。
